# Порівняння SPARQL і Cypher

Ті самі факти імпортовано в Neo4j і прочитано з Turtle через RDFLib. Усі п’ять пар повернули однакові рядки в однаковому порядку. У таблиці наведено кількість символів повного запиту й медіану п’яти вимірювань після прогріву. Cypher виміряно від Python через Bolt із читанням рядків, SPARQL — локально в RDFLib. Час описує ці конкретні середовища і малий набір.

Таблиця 7. П’ять критеріїв порівняння мов

| Критерій | Cypher | SPARQL |
|---|---|---|
| Читабельність | Шаблон з вузлами і стрілками відображає напрямок ребер. | Шаблон складається з RDF-трійок. Скорочені предикати потребують PREFIX. |
| Довжина | Радше залежить від кількості міток і властивостей у шаблоні. | Довжину збільшує PREFIX, а скорочений шлях через / може її зменшити. |
| Час | П’ять вимірювань включають Bolt і десеріалізацію драйвера. | П’ять вимірювань включають локальну обробку RDFLib. |
| Зручність | WITH, shortestPath і типізовані ребра зручні для обходу залежностей. | PREFIX, шляхи властивостей та GROUP BY зручні для запитів до RDF. |
| Обмеження | Для автоматичного OWL-виведення потрібне окреме рішення. | Шлях властивостей знаходить досяжні кінці. Для повернення повного маршруту з довжиною потрібен інший прийом. |

## Text to Cypher

На вході десять запитань, схема в prompt_v1.txt і сирі кандидати з tests/t2c.jsonl. Скрипт перевіряє кінцевий LIMIT 1–100, виконує EXPLAIN і відхиляє попередження про невідомі елементи схеми. Кандидатів виконує тимчасовий обліковий запис з ролями PUBLIC, reader. Контрольний запис відхилено з кодом `Neo.ClientError.Security.Forbidden`. Результат кожного кандидата зіставляється з еталонними рядками.

Правильні кандидати — 7/10 (70%) на підготовленому контрольному наборі. Три помилки навмисно включено до набору для перевірки, тому метрика характеризує контрольний запуск.
