## Запуск у Windows PowerShell

1. Розпакуйте архів. У VS Code відкрийте папку `lab09`, а в ній — Terminal → New Terminal. Запустіть Docker Desktop. Ця папка має містити `compose.yaml` і `run_lab.py`.
2. Створіть оточення та встановіть залежності. Код перевірено на Python 3.12, Neo4j Enterprise 5.26.0, GDS 2.13.1, neo4j Python driver 5.26.0, RDFLib 7.1.4. Enterprise використано для справжньої вбудованої ролі `reader`. Для Docker потрібен дозволений вам режим ліцензії; `eval` означає оцінювальний режим. Якщо у вас доступне ліцензоване навчальне середовище Neo4j Enterprise 5.x з GDS, можна використати його замість Docker, вказавши `NEO4J_URI`, помістивши CSV в його import-каталог і запускаючи програму у спеціально відведеній лабораторній базі.
   
   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
3. Набір CSV/Turtle вже є в архіві. Якщо треба відновити його, виконайте `.\.venv\Scripts\python.exe prepare.py`. У тій самій консолі задайте пароль для нової ізольованої бази та підніміть контейнер.
   
   ```powershell
   $env:NEO4J_ACCEPT_LICENSE_AGREEMENT = "eval"
   $secure = Read-Host "Задай пароль Neo4j, мінімум 8 символів" -AsSecureString
   $env:NEO4J_PASSWORD = [System.Net.NetworkCredential]::new("", $secure).Password
   docker compose up -d
   docker compose logs --tail=30 neo4j
   ```
   
   Дочекайтеся рядка `Started.`. Початковий пароль застосовується при створенні нового тому. Для існуючого тому введіть той пароль, з яким його створили. Якщо Bolt ще не готовий, перевірте логи й повторіть запуск Python після старту. Якщо порт зайнято, зупиніть свій інший локальний Neo4j перед запуском цієї бази.
4. Запустіть перевірки. Програма імпортує граф двічі, виконує CQ й SPARQL, запускає алгоритми та PROFILE і тестує кандидатів через роль reader.
   
   ```powershell
   .\.venv\Scripts\python.exe run_lab.py
   ```
   
   JSON-файли з фактичним виводом будуть у `results/`. Додані Markdown-звіти містять підсумок контрольного запуску. У разі нового запуску підставте свої виміряні результати у звіт.
5. Для скриншотів відкрийте [Neo4j Browser](http://localhost:7474), увійдіть як `neo4j`. Виконайте окремими командами:
   
   ```cypher
   MATCH (n:Resource) RETURN count(n) AS nodes;
   MATCH (:Resource)-[r]->(:Resource) RETURN count(r) AS relationships;
   SHOW CONSTRAINTS;
   SHOW INDEXES;
   MATCH p=(:VirtualMachine {id:'vm_01'})-[:DEPENDS_ON*1..4]->() RETURN p;
   MATCH (n:Resource) RETURN n.id, n.pagerank, n.community ORDER BY n.pagerank DESC, n.id LIMIT 10;
   ```
   
   Підписи до власних знімків: «Кількість вузлів і зв’язків після імпорту», «Обмеження та індекси Neo4j», «Ланцюг залежностей vm_01», «Перші 10 вузлів за PageRank».
6. Для репозиторію Hub відкрийте його папку, перейдіть на гілку `lab09` (або створіть її через `git switch -c lab09`), скопіюйте файли з архіву, перевірте `git status`, додайте папку `lab09`, закомітьте і надішліть у свій remote. За наявності однойменних файлів спочатку звірте, що зберігаються ваші попередні роботи. Звіт підготуйте за шаблоном викладача на основі `docs/report.md`. Звіт DOCX теж є в папці `docs`. Для зупинки контейнера виконайте `docker compose stop`.

## Що пояснити на захисті

1. **LPG і RDF.** У LPG властивості можуть мати і вузли, і ребра. RDF представляє знання трійками з URI; у нашому RDF походження ребер збережено реїфікацією. LPG зручна для навігації залежностями, RDF — для інтеграції семантичних даних і OWL.
2. **Запит CQ10.** Стрілка веде від залежної ВМ до її залежності. Починаємо з vm_05 і йдемо проти цього напрямку на 1–4 кроки. `min(length(p))` повертає найменшу глибину впливу для кожної ВМ. Змініть верхню межу з 4 до 3 і поясніть зникнення vm_01.
3. **Обмеження та індекси.** Унікальність id зупиняє дублікат; індекс site дає швидший доступ до потрібного майданчика, що видно в PROFILE за оператором і DB Hits.
4. **PageRank і Louvain.** PageRank оцінює структурну центральність. Louvain поділяє вузли на спільноти за щільністю зв’язків. Подробиці та числа дивіться в `docs/gds_report.md`.
5. **Text-to-Cypher.** Назва мітки, напрямок ребра та глибина суттєво впливають на відповідь. Перевіряємо план, обмежуємо розмір відповіді, виконуємо через роль reader і звіряємо рядки з еталоном.
